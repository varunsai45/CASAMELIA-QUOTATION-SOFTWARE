There are **32 differences** between visible computed prices and hidden lookup prices. Each has its own `price_conflicts` record. Both original values are immutable provenance. Official price is null until an Admin chooses a source. Resolution stores source, value, user, date and audit entry. An unresolved product is excluded from Sales search and cannot be generated by submitting its ID directly.

Eight combinations are **On Request**. No numeric value is invented. Admin may approve a price through Master List editing; this is audited. No duplicate combinations were found. Reimport is idempotent and does not overwrite Admin changes. Duplicate source combinations cause import to stop with a report.

| Auto Qoutation column | Application field |

Observed calculations:

- Ordinary rows: `M = K × L`, `O = E`, `P = M × N × O`.
- Row 18 uses explicit **86.2 running feet** rather than width × length.
- Row 31: `O31 = E31 + G31`, with Other description **Seating Cushion** and **₹1,210 rate addition**.
- Row 56: `P56 = M56 × N56 × O56 + 4000`: **₹4,000 once**. The automated workbook changes this to a rate addition. The application preserves the original and exposes the two charge types separately.
- `new format` M28 and M34 use quantity × rate without area. The editor supports a per-unit mode.
- Section totals are sums of valid lines. Subtotal is the sum of section totals.
- GST is 18% by default, matching `(P68 × 1.18) − P68`. Configuration is snapshotted for each quotation.
- Grand total is subtotal + GST. Decimal arithmetic retains measurement/rate precision; monetary amounts are rounded to paise using half-up rounding. The PDF shows two decimals so printed sums reconcile.
- Original H71 is fixed text; `new format` A45 references a custom `RupeeFormat` function. The application generates Indian currency words from the actual final total, including paise.

Empty unconfigured rows have null calculated amounts. They do not participate in totals or appear in the PDF. A configured but incomplete row can be saved in a draft and blocks generation with a specific message.

## Company, terms and PDF

Company information is copied verbatim from H2, including addresses, contact information and existing spelling. All **13 terms** are imported verbatim from I73:I85. The extracted original logo is used without editing.

Print settings: **A4 portrait**, left/right **0.75 inch**, top/bottom **1 inch**; 300 DPI. There is no specified print area, repeated print titles, custom header/footer or manual page-break layout. All original row heights in the quotation are 15 points except row 7 (46.5 points). Literal 15-point heights would clip the long terms; generated rows expand to fit real text.

The PDF follows the H:P quotation region: company at the top left, logo at the top right; customer/address/project/date block; blue `#B8CCE4` headers; pale yellow `#E9E791` section and total rows; thin grid borders; matching field order. Column proportions are adapted to the available A4 width. Section headers repeat across splits; blank sections are omitted. Terms stay together when they fit a page. Windows uses installed Calibri; Linux uses DejaVu Sans because Calibri is not redistributed.

## Historical protection

`quotations`, `quotation_sections`, `quotation_items`, and `quotation_terms` store the current working snapshot. Every generation creates an immutable `quotation_versions` row containing its entire pricing/terms/company/tax snapshot and PDF bytes in one transaction. Earlier versions are never updated by edit or download endpoints. Downloads return stored bytes. Editing keeps snapshotted rates and terms; an explicit **New quotation with current prices** action creates a separate quotation using current Master List values and current terms.
